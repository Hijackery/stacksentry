# Версии и обновление

StackSentry использует Semantic Versioning для номера версии, но **не публикует
GitHub Releases и теги**. Актуальная и единственная поддерживаемая версия
находится в ветке `main`; обновление всегда скачивается из неё.

## Где видна версия

- В коде: `stacksentry/__init__.py` (`__version__`).
- В боте: `/version` показывает версию, Python, ОС, пакетный менеджер и панель.
- В терминале: `stacksentry-menu version`.
- Commit установки: `$PREFIX/.stacksentry-install` (пишет установщик).

## Проверка обновлений

- В боте: «❓ Помощь» → «🔄 Проверить обновления», раздел «Помощь» в Mini App
  или `/updatecheck`.
- В терминале: `sudo stacksentry-menu update-check`.
- Проверка сравнивает commit установки с последним commit `main` через GitHub
  API. Если метаданных нет (старая установка), сравниваются версии; для точной
  проверки один раз запустите установщик.

## Установка обновления из бота

Когда обновление найдено, появляется кнопка «⬆️ Обновить StackSentry».

1. Нажмите кнопку.
2. Подтвердите действие.
3. Если включена 2FA, введите свежий TOTP (обновление перезапускает бота, поэтому
   нужен код не старше 2 минут).
4. Бот поставит задачу в отдельный systemd-юнит (или фоновый процесс вне
   sandbox), установщик скачает `main`, сохранит `.env` и состояние и
   перезапустит службу.

Права: `stacksentry-ctl update_bot` разрешён в sudoers; установщик должен
принадлежать root и быть недоступен на запись группе/другим. Пин
`UPDATE_SHA256` в `/etc/stacksentry.conf` опционален; без него установщик
обновляется из выбранного `UPDATE_REF` (по умолчанию `main`).

## Ручное обновление

```bash
# из меню
sudo stacksentry-menu          # пункт 24

# или установщиком
sudo bash /opt/stacksentry/install.sh --yes --ref main
```

Конфиг и состояние сохраняются, если не передан `--force-config`.

## Откат

- Код: повторно установите предыдущую копию из резервной копии каталога или
  форка с нужным коммитом.
- Конфиг: `.env` и каталог состояния (`STATE_PATH`, по умолчанию
  `/var/lib/stacksentry`) стоит сохранять перед крупными обновлениями.
- Если обновление сломало запуск: `sudo stacksentry-menu logs 100`,
  `journalctl -u stacksentry-bot -n 100`, затем восстановите `.env`/код и
  перезапустите службу.

## Поддержка версий

Поддерживается `main`. Критические исправления попадают в `main` и становятся
доступны кнопкой проверки обновлений; отдельные патч-релизы не выпускаются.
Политика безопасности описана в [SECURITY.md](../SECURITY.md).
